# Граф зависимостей Python-пакетов — вариант 6

Программа строит граф прямых и транзитивных зависимостей Python-пакета. Обход выполняется алгоритмом BFS без рекурсии; зависимости пакетов одного уровня загружаются параллельно, не более пяти запросов одновременно. Повторно встретившиеся пакеты не запрашиваются, связи и циклы сохраняются.

## Настройки

Программа читает файл `config.toml` из текущей рабочей папки:

```toml
package = "requests"
repository = "https://pypi.org"
test_mode = false
print_tree = false
include_extra = false
filter = ""
reverse = false
reverse_candidates = []
```

- `package` — исходный пакет.
- `repository` — базовый URL PyPI или путь к тестовому файлу.
- `test_mode` — использовать тестовый файл вместо PyPI; по умолчанию `false`.
- `print_tree` — допечатать ASCII-дерево после описания PlantUML; по умолчанию `false`.
- `include_extra` — включать зависимости с маркером `extra`; по умолчанию `false`.
- `filter` — подстрока для исключения пакетов; пустая строка отключает фильтр.
- `reverse` — выводить пакеты, которые прямо или транзитивно зависят от исходного.
- `reverse_candidates` — список пакетов для обратного поиска в PyPI; в тестовом режиме используется весь файл.

В PyPI-режиме имена пакетов нормализуются: буквы приводятся к нижнему регистру, последовательности `-`, `_` и `.` заменяются на `-`. В тестовом режиме используются имена из заглавных латинских букв. Фильтр чувствителен к регистру и применяется к этим именам; если он совпадает с исходным пакетом, граф не строится.

Ограничения версий и условия сохраняются в ASCII-дереве. Версии не подбираются, условия окружения не вычисляются. При `include_extra = false` любая запись, содержащая переменную `extra` в условии, исключается целиком. Поэтому граф может отличаться от результата установки через `pip`.

## Тестовый репозиторий

Укажите файл вместо URL:

```toml
package = "A"
repository = "test.txt"
test_mode = true
include_extra = false
filter = ""
```

Файл содержит по одному пакету на строке: имя, двоеточие и зависимости через пробел. Допустимы только заглавные латинские буквы. Каждый пакет объявляется один раз, в том числе пакеты без зависимостей; все упомянутые зависимости должны быть объявлены. Пустые строки и комментарии запрещены.

Например, общий пакет `D` и цикл `D → A`:

```text
A: B C
B: D
C: D
D: A
```

При `package = "A"` и пустом фильтре видны связи `A → B`, `A → C`, `B → D`, `C → D`, `D → A`.
В готовом `test.txt` дополнительно есть `C → E`. При `filter = "B"` связь с `B` исчезнет,
а `D` останется доступным через `C`.

Для проверки цепочки можно заменить содержимое файла на:

```text
A: B
B: C
C:
```

Ожидаемые связи: `A → B` и `B → C`. Пакет без зависимостей отображается отдельной вершиной.

## Обратные зависимости

В `config.toml` установите `reverse = true`, `test_mode = true`,
`repository = "reverse-demo.txt"` и `filter = ""`, затем выполните `make run`.

| Исходный пакет | Результат | Что проверяется |
| --- | --- | --- |
| `D` | `A, B, C, E` | Общая зависимость и цикл `B → D → B` |
| `F` | Нет обратных зависимостей | Изолированный пакет |
| `D` с `filter = "C"` | `A, B` | Фильтр также убирает путь от `E` |

Программа строит индекс рёбер в обратном направлении и запускает тот же BFS без рекурсии.
Исходный пакет не печатается повторно, даже если он входит в цикл.
Поиск охватывает весь тестовый файл, включая пакеты вне прямого графа исходного пакета.
У [JSON API PyPI](https://docs.pypi.org/api/json/) нет запроса входящих рёбер,
поэтому в сетевом режиме перечислите область поиска в `reverse_candidates`.
Например, для `package = "idna"` задайте `reverse_candidates = ["requests", "httpx"]`.

## Этап 5. Визуализация

При `reverse = false` программа выводит [описание PlantUML](https://plantuml.com/component-diagram).
Каждый пакет представлен компонентом, стрелка направлена от пакета к его зависимости.
В диаграмме остаются все рёбра, в том числе циклические. В дереве ветви заканчиваются на
пометке `[цикл]` или `[уже показан]`.

Чтобы сохранить описание для PlantUML, задайте `print_tree = false`:

```bash
make run > graph.puml
```

Для демонстрации трёх пакетов установите `repository = "https://pypi.org"`,
`test_mode = false`, `reverse = false`, `include_extra = false`,
`print_tree = true` и `filter = ""`. Запустите `make run` отдельно для каждого значения `package`:

| Пакет | Что видно на диаграмме и в дереве |
| --- | --- |
| `requests` | Четыре прямые зависимости: `certifi`, `charset-normalizer`, `idna`, `urllib3` |
| `httpx` | Общий `certifi`, цепочка `httpx → httpcore → h11` и условные ветви `anyio` |
| `typing-extensions` | Одна вершина без рёбер |

Пример фрагмента дерева для `httpx`:

```text
httpx
|-- anyio
|   |-- exceptiongroup>=1.0.2; python_version < "3.11"
|   |   `-- typing-extensions>=4.6.0; python_version < "3.13"
|   |-- idna>=2.8
|   `-- typing-extensions>=4.16.0; python_version < "3.15" [уже показан]
|-- certifi
|-- httpcore==1.*
|   |-- certifi [уже показан]
|   `-- h11>=0.16
`-- idna [уже показан]
```

У `pip` нет встроенного графического вывода графа. Для сравнения использован его штатный
[отчёт о разрешении зависимостей](https://pip.pypa.io/en/stable/reference/installation-report/):

```bash
python3 -m pip install --dry-run --ignore-installed --only-binary=:all: \
  --report pip-report.json requests httpx typing-extensions
```

Проверка в Python 3.15: четыре зависимости `requests` совпали с отчётом; у
`typing-extensions` зависимостей не было. У `httpx` совпали обычные ветви,
но `pip` не выбрал `exceptiongroup` и не потребовал `typing-extensions` для
`anyio`: маркеры соответствующих версий Python оказались ложными.
`typing-extensions` присутствует в общем отчёте только потому, что указан явно.
Наш граф показывает опубликованные связи из JSON API PyPI без вычисления этих маркеров;
`pip` выводит конкретные версии для текущего окружения.

## Сборка и запуск

Нужен Go версии, указанной в `go.mod`. Из корня проекта:

```bash
make build
make run
make test
```

`make test` запускает существующие проверки конфигурации. Для работы с PyPI необходимо сетевое соединение; тайм-аут одного запроса составляет 10 секунд. Ошибки отдельных пакетов сохраняются в графе и выводятся рядом со связями.
